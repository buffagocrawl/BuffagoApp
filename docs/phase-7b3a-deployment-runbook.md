## Existing function comparison and trigger order

`source-comparisons.json` compares extracted safe repository body text to `md5(pg_proc.prosrc)`:

- Buffacoin guard, friend-notification and owner-pseudonymization checkout body MD5 match the reported production body MD5 exactly, including CRLF. Guard checks the atomic-write GUC; pseudonymization sets deletion timestamp and refuses reidentification. Friend notification calls social/blocked-pair helpers, reads friendships/preferences/flags, and inserts a deduplicated outbox record. Matching body text does not establish those dependent implementations/configuration, file provenance or runtime lock behavior.
- Two gallery helper body MD5s match after LF normalization. Reviewed validation enforces identity/current eligible media; count refresh takes a separate `wing-photo-votes:<submission>` advisory lock then updates media gallery counters. The fixture executes these candidates; new Jury code never calls/replaces them or writes gallery counters.
- Local Mango priority-helper body differs. Its fixture candidate is explicitly unverified for production. Badge reward, approval, derivative-queue, referral/profile and Storage helper bodies remain surrogates where unavailable. Do not call them production equivalents or certify MD5 from their surrogate implementation.

Same-event PostgreSQL triggers run in name order. New rating BEFORE identity lock precedes `guard_buffacoin_rating_writes`. On AFTER INSERT, friend notification precedes Want cleanup; `trg_rating_after_insert` follows it. AFTER UPDATE old-identity Favorite cleanup runs before new-identity Want cleanup. Existing code can therefore observe different intermediate collection state inside the same transaction. Fixture notification/reward witnesses and failure injection demonstrate atomic rollback; actual reward/outbox/wallet locks, caller isolation/retry and transitive behavior remain application gates. Multirow operations can deadlock; READ COMMITTED plus whole-transaction retry is required. Guest null-owner rating events also reach the cleanup isolation guard.

Official reference: [PostgreSQL trigger behavior](https://www.postgresql.org/docs/17/trigger-definition.html), [FK actions](https://www.postgresql.org/docs/17/ddl-constraints.html), [Supabase grants and RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).

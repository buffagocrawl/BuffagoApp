## Adapter implementation and limits

The library has no CLI and does not connect on import. Only the direct host/5432/postgres identity is accepted. `sslmode=verify-full`, explicit CA hash, absolute pinned psql17.6, protected external PGPASSFILE, minimal environment, case-insensitive PG override refusal, signed Ed25519 action/target/artifact/actor/expiry/window decisions, strict preflight, same-backend proof, locked drift checks and atomic existing kernel execution are implemented. Explicit signed history/ledger/behavior dispositions and matching read-only versus apply authorization are required; nonempty planning strings cannot pass those gates. An exclusive external attempt file is fsynced before writes; credential/function-body dumps are excluded. Independent read-only post-COMMIT confirmation is required. Protocol EOF, SQLSTATE and whole-attempt/approval-window deadline stop without replay.

SCRAM authentication is mandatory (`PGREQUIREAUTH=scram-sha-256`); GSS encryption is disabled and TLS1.2 is the minimum. This refuses a server that skips authentication even when its TLS certificate is trusted. [PostgreSQL17 authentication and TLS parameters](https://www.postgresql.org/docs/17/libpq-connect.html#LIBPQ-PARAMKEYWORDS) and [libpq environment variables](https://www.postgresql.org/docs/17/libpq-envars.html) define these independent checks.

The trusted approval key/store, actual human decisions, protected filesystem/credential-provider ACL attestation, reviewed psql distribution/dependent libraries/CA and approved pre/post catalog digests must be provisioned and independently reviewed. A caller-generated test key is **not** a production trust anchor. The signed protected-files evidence field is an attestation requirement, not an automatic Windows ACL audit. No production connection/session has been opened. Full production-target `runApproved` end-to-end parity, operational review and later authorized read-only target proof remain gates; compositional fixture tests alone do not grant deployment readiness.

# Find-and-rate-wings journey

Discovery → list/map → restaurant detail → rating controls/tags → submit → reward → next action is Buffago’s strongest intended loop. Rating contracts and reward/idempotency tests are green historically; UI mechanics are CI/partial EV, live submission is not validated.

Keep Wingdex prominent. Clarify the rating CTA and outcome in plain language, show submitted restaurant/name and reward, and offer one next action. **Before internal beta**, validate a clean emulator path and error retry; do not redesign scoring without user evidence. Acceptance: a user completes one rating, sees a durable confirmation, and can return to the restaurant list without losing context.

# First-time-user journey

Path: launch → value proposition → auth → onboarding/state/preferences → discovery → detail → first rating → reward → Home. Evidence: prior Android clean-onboarding EV, rating/auth contracts CV, current source CI, no live OAuth or observed participant task data.

Assessment: time-to-value is at risk because authentication and setup precede the clearest payoff. The meaningful moment is submitting a first rating; reward and a single next restaurant should immediately follow. The main abandonment risk is encountering account, location, state, preferences, XP, crawl and social concepts before seeing a good wing destination.

Recommendation: **before internal beta**, make the first post-auth screen lead with one explicit “Find wings near me” or selected-state action and delay optional progression explanations until after a successful rating. Benefit: clearer activation; risk: lower early feature discovery; effort: small/medium. Acceptance: a fresh user can reach a restaurant and identify the rating CTA without an explanatory modal; validate with Cayenne onboarding→Wingdex→rating smoke and moderated task testing.

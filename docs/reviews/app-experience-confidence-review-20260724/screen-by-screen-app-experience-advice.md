# Screen-by-screen advice

Evidence is CI unless noted; no screen-render check is comprehension proof. Common before-beta standard: a visible primary action, plain label, 44pt targets, text-scale resilience, named error/retry; later experiments require user testing.

| Screen | Goal / actual focus | Clear / confusing or unnecessary | Before-beta / later / recommendation |
|---|---|---|---|
| Welcome, Sign in | Understand and continue | Auth copy clear; value can arrive too late | State wing promise first / test browse-first; Clarify |
| Onboarding, State | Set context | necessary data vs setup burden | defer optional preferences / test order; Simplify |
| Search, Wingdex list/map | Find venue | core labels; list/map choice | make search/rate dominant / test defaults; Keep |
| Restaurant detail, Rating, Completion | Judge and receive reward | core task / scores-tags-reward language | single CTA and durable success / test tag load; Clarify |
| Home | Choose next action | all systems compete | one dominant recommendation / test card order; Simplify |
| Crawl, Mission, Streak | Plan/return | useful after value / early game vocabulary | contextual intro / test timing; Reveal progressively |
| Notifications | Resume useful task | destination reliability unknown | validate deep-link/recovery / test tone; Needs real-user testing |
| Passport | See exploration | collection metaphor | pair with plain cue / test motivation; Clarify |
| Buffaverse | Advanced progress | branded but opaque | unlock + one-line purpose / test direction A/B; Move later |
| Referrals | Invite | qualification/status complexity | keep disabled/safe / test moment after value; Hide behind progression |
| Social, Leaderboards, Friends | Community/status | may be empty | empty-state purpose / test local density; Needs real-user testing |
| Profile, Settings, Deletion | Manage account | trust controls | validate destructive confirmation/a11y / test wording; Keep |

Hierarchy advice: rates and nearby places outrank status. Interaction: preserve context on back and retries. Performance: retain loading skeletons/feedback and validate actual images. Mascot: use beside success/empty/error, not as an extra competing CTA.

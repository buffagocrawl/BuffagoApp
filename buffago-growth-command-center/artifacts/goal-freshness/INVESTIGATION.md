Root cause: producer cadence. The fixed private cloud feed still held CT=228, with state aggregation completion timestamp 2026-10-30 13:28:54.653287 UTC and feed production timestamp 13:28:54.653447 UTC, before the import. The latest producer run 41063557990 succeeded. No later producer run existed at investigation time; the existing producer ran only with the nightly analytics workflow or a manual dashboard-only dispatch. Pi's ten-minute pulls repeatedly fetched that same valid old object. Its cache showed CT=228 and a successful last pull at 14:01:20.713347 UTC, refresh_failed=false. This was fresh delivery of older database aggregates, not a failed request or stale social-report selection.

The display is native Tk, not a browser. Its minute repaint reloads the local cache and never recollects production counts. Refreshing a browser cannot regenerate the cloud aggregate. The former SOURCE FRESH badge checked social timestamps but not the age of state counts, making recent device delivery easy to misinterpret.

It has no Meta credentials or collector/publisher steps. It serializes with the existing analytics producer using the same concurrency group without cancelling running work. Existing analytics/publisher cron expressions, recovery controls and Pi refresh units are unchanged.

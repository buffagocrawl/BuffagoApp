## Defect fixed and validation

`app/auth/login.jsx` previously replaced the modal login screen with `/(tabs)/home` even when Home's tabs were already underneath it. Native signup/photo handoffs worked, but ordinary no-intent signin after signout produced an empty native screen with a real persisted session. Waiting 45 seconds did not reach Home; screenshot 31 and native trace retain that failure. Cold restart recovered Home (32), which was not counted as a successful pre-fix signin landing.

The normal Home return now calls `router.dismissTo('/(tabs)/home')`; explicit Wing Shot/saved-destination routes still use `replace` with the existing exactly-once/account checks. This unwinds the auth modal to the existing Home rather than replacing it with another copy of the tabs route. Installed Expo Router supports the API; its documented fallback replaces when the destination is absent from history. [Official stack API](https://docs.expo.dev/router/advanced/stack/#dismissto-action).

Native post-fix ordinary signin reached stable Home in the first successful poll (~6s including UI dump time), before any restart; cold restart retained it. Post-fix existing photo invitation was retested to the preselected uploader, then canceled and cold restarted. No completion, intent, signup/session, seed-import, upload or backend contract behavior changed by this client fix. Regression executes the actual login component and duplicate auth events, asserting ordinary signin dismisses once and Wing Shot intent still replaces once. Actual native evidence, not this mock, closes the exercised Android gate.
